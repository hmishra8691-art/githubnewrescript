## Root causes and fixes

**S1 / O1: no "Other, specify" box on a grid row**

- **Cause:** the Studio offered `other_specify` on matrix rows (`allowedRowFlagsFor`), but no part of the system read it from a row. `otherOptions` reads options only, so:
  - no renderer drew a box;
  - the validator asked for nothing;
  - the export had no column.
- **Fix, in the engine (`otherSpecify.ts`):**
  - A row's box is stored like an option's box: one key per box, under code `row:<rowCode>`. The prefix keeps it apart from a column option with the same code.
  - `otherTextsOf`, `clearOtherText`, the flattener (including loops), the variable dictionary (`VAR_<row>_other`), `otherSpecifyEntries` and piping (`{{Q1[r9].other}}`) all read the new key.
- **Fix, in the renderer:** one component, `RowLabel`, draws the label and the box. Every tabular grid uses it:
  - Single and Multi matrix;
  - Likert, Rating, Star and Slider matrices;
  - Mixed and Constant-Sum matrices;
  - the editable table.
- **Validation is about the pair.** The row's box is always visible, so the rules link the rating and the text:
  - an answered row needs its text, unless Other text is set to optional;
  - typed text needs its row answered;
  - a row with neither is not used. A required grid does not force a rating of an "other" the respondent does not have, and the constant-sum target does not apply to it.
- **The Studio offers the property only where it can be drawn.** Swipe cards, drag chips and bipolar pairs have no row label to put a box beside, so the property is not offered there (`rowOtherBoxSupported`).

**S2: rows never randomized**

- **Cause:** the preset seeded `settings.randomizeRows: true`, which nothing reads. Row order comes from the question's `randomization`.
- **Fix:**
  - The preset now switches on `randomization { scope: "rows", method: "shuffle" }`. This is seeded per respondent, stable across resume, leaves anchored rows in place, and is visible in Properties → Randomization.
  - Variant defaults can now carry `randomization`, and both the picker and the type switcher apply it.
  - Switching away removes randomization only if it is still exactly what the preset seeded.
  - Questions saved with the dead setting are migrated when they are loaded (`normalizeLegacyRowRandomization`):
    - Off → rows are shuffled.
    - Already shuffling another axis → rows are added as a second axis.
    - Already shuffling rows → unchanged.

**S3 / S4 / S6: List / Form fields**

- **Fields one at a time (S3).**
  - Cause: Open Text List and Numeric List arrived with no fields, which drew the older numbered list: N identical boxes from an "item count", all sharing one Required setting.
  - New questions now start with three ordinary fields. **+ field** adds one more.
  - Each field has a **Required / Optional** switch. The question's Required setting still means "every field" when no single field is marked, and the editor says so.
  - The item-count box is gone. A question that still uses it shows a notice and a **Make N separate fields** button. The button is disabled once the survey has live responses, because the stored answers would change shape.
- **No star (S4).**
  - The star is gone, in the Repeating Form too.
  - Above the fields, one sentence states exactly the rule the validator enforces, for example "“Email” is required.", "Required: Name, Email." or "All fields are required."
  - It is built by `requiredFieldsNote` from the same `fieldIsRequired` the validator uses, so the two cannot disagree. It can be translated through the UI-string table.
  - Inputs carry `aria-required`.
- **Label gap and position (S6).**
  - Cause: a fixed label column of 150px.
  - The label column is now as wide as this question's longest label (capped, so long labels wrap) and every box starts on the same line.
  - New setting `fieldLabelPosition`: Left (the existing layout, and the default), Above or Right.
  - On phones, and in the preview's Mobile view, every position stacks with the label first.

**S5: "Changed elsewhere" when nothing changed elsewhere**

The database refuses a draft write whose base revision is stale, which is correct. The false alarms came from the client.

1. **Two saves on one revision.**
   - Every writer waited for the save in flight and then started its own, without checking again after waking.
   - An autosave tick and a flush (Preview, Test, Save version, an Intelligent apply, a tab change) waiting on the same save woke together and sent the same revision. One was accepted. The other was refused as "changed elsewhere", and autosave stopped.
   - Fix: all draft writes now go through a queue (`serialRunner`, `lib/draftSave.ts`). Each starts only after the previous one has finished, so it reads the revision that save returned.
2. **A save whose response was lost.**
   - If the server accepted a write but the response never arrived, the editor was one revision behind its own work.
   - The refusal includes the server's draft. `isOwnWrite` compares it with what this editor sent, using the same schema defaults and element ids the server applies, and ignoring key order. When the server holds only this editor's own work, the editor adopts the server's revision and saves again (once).

A real conflict, such as another tab, another person, or a version restored elsewhere, still stops autosave and still says so. The browser suite covers all three cases against a server that applies the same revision guard.

**O2: HTML Text Box**

- **Cause:** the block's content editor opened on the Visual tab, a word processor. `<b>Welcome</b>` typed there is stored as text describing a tag (`&lt;b&gt;`), so respondents saw the code.
- **Fix:**
  - On an HTML block the content field is labelled **Content HTML** and opens on the HTML tab, with a larger source box and an example placeholder.
  - Content that already holds typed tags shows a notice with **Render it as HTML** (`typedMarkup` / `decodeTypedMarkup`). Text such as "5 &lt; 7" that is not a tag is left alone.
- **"Unnecessary text box":** the HTML block showed an Instruction editor and a Required control, but it never draws the instruction and takes no answer. Both are now hidden on HTML blocks, and so is Attention check. An instruction already written on one is kept, shown, and can be moved into the content with one click.
- **"Changes save automatically."** (highlighted in red on the screenshot) was static text that also showed while a save was being refused. It now reports the actual save state ("Saving…", "✓ All changes saved", "Not saved — see the save status at the top", and so on), from the same state the header uses.

**P1: Rating Matrix (1–5)**

- Selecting the type gives columns 1–5 as before.
- **Builder:** the order is now Rows → Columns → **Rating scale & labels** → Display settings (Properties → Header repeat). The new block has:
  - **Rating scale:** 1–3, 1–4, 1–5, 1–7 or 1–10.
  - **Column labels:** Numbers or Text labels. Text uses the standard words (Very Poor, Poor, Neutral, Good, Excellent, with equivalent sets for 3, 4 and 7 points), editable per point.
  - A strip showing how the header will read.
- **Labels are stored in the option labels.** The codes stay 1–N, so the stored numbers and the analysis do not change. The words are the value labels in the export.
  - Switching to Numbers keeps the words in `meta.textLabel`, so switching back restores them.
  - Changing the scale size takes that size's standard words.
- **Renderer:** the chip-per-row layout is now a grid. The points are column headers, with a circle under each header in every row (the Prince "desired" screenshots). The ends are labelled when they are set. On phones and in the Mobile preview it stacks, and each circle shows its own caption.
- Switching a Likert grid to Rating Matrix now replaces Likert's default columns (Strongly disagree … Strongly agree) with 1–5. Columns the programmer edited are kept.

**P2: Header Repeat**

- **New setting `headerRepeat`:**
  - `"off"`;
  - `"auto"`, which repeats every 10 rows;
  - a number: 5, 10, 15, 20, 25, or a custom count.
- **Default when unset:** off for grids of 20 rows or fewer, Auto for longer grids. On a 16–20 row grid the editor suggests turning it on.
- **Where to set it:** Properties → **Header repeat**, offered on every grid that draws a column header:
  - Single, Multi and Randomized-rows matrices;
  - Likert, Rating and Semantic Differential;
  - Mixed, Numeric, Text, Dropdown and Constant-Sum;
  - Slider matrix, in both layouts;
  - the editable table.
- **Semantic Differential** had no header at all. It now shows its scale points above the columns.
- **Display only:** the repeat reuses the same header cells and is `aria-hidden`, because the real header still labels every cell. No column, value or variable is added.
- **Layout:** in a table the repeated cells line up exactly with the header (tested). Stacked phone layouts, which have no header, hide the repeats. Keyboard navigation in the editable table skips repeat rows.
- Star rows, drag-and-drop matrices and swipe or card variants have no column header to repeat, so the setting is not offered for them. See "Not done".

## Script UI improvements

- **Question cards:**
  - The type is shown by name (for example "Rating Matrix (1–5)" rather than `rating`). The internal key is kept in `data-key`.
  - What the question is made of is shown at a glance: "3 rows × 5 columns", "4 options" or "3 fields".
  - Required questions have a **Required** pill.
  - An empty question says "No question text yet" in the warning tone instead of a grey "untitled".
- **Actions:** the row's actions stay quiet until the card is hovered, focused or open. On touch devices they are always visible.
- **Open state:** an open card has an accent bar.
- **Keyboard:** each card has a caret button that opens and closes the editor (`aria-expanded`), so this works from the keyboard as well as by clicking.
- **Feedback:** after **Duplicate** or **Move**, the affected card pulses and scrolls into view, and Duplicate shows a toast naming the copy.
- **Save line:** the bottom of the open question reports the real save state.
- **New controls** (segmented choice, Required/Optional switch, rating header strip) use the existing design tokens. Motion respects `prefers-reduced-motion`.

## Conflicts and interpretations

- **O2 vs the 06-10 brief (R2: one canonical content).** Oweas asks to "remove the Question Text field and keep the Content HTML field". 06-10 R2 removed the separate HTML Content field and made the text the content. Both are honoured:
  - There is one field.
  - On an HTML block it is the **Content HTML** field, HTML-first, rendered as written.
  - The genuinely unnecessary boxes (Instruction and Required) are gone from the block.
  - No second content field was reintroduced.
- **S6 default position.** The sheet lists "Above the input (current/default layout)". The screenshots show labels on the left, which is the current layout. I kept Left as the default so existing surveys look the same, and Above is one click away. If you want Above to be the default for new questions, it is one line in the renderer.
- **S4 wording.** The sheet's examples ("One field is mandatory", "Please complete at least one field") describe an "at least one" rule, which the engine does not have. The note states the rule that actually applies (which fields, or all of them), so it never promises something the validator will not enforce. An "at least N fields" rule would be a new feature.

## Not done / needs attention

- The preview's "resume where you were" (sessionStorage, keyed by survey id) explained the long-standing p0-runtime-contract and tester-fixes failures. Those suites reused one survey id across scenarios. The suites now start each scenario as a new respondent, and the product behaviour is unchanged.

## Data and schema changes

All changes are additive and optional:

- Settings `fieldLabelPosition`, `headerRepeat` and `ratingLabels`.
- Variant defaults can carry `randomization`.
- Row other-specify text is stored under `<qid>__other__row:<code>` and exported as `VAR_<row>_other`.
- Three new UI strings (`fields_required_*`).
- Open Text List and Numeric List get starter fields.
- `normalizeQuestion` (run when a question is parsed) adds the `randomizeRows` migration.
