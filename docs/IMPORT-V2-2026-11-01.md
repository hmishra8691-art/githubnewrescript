# Intelligent Survey Import — I1 to I8 (2026-11-01)

The Phase 1 inspection (project doc `claude/import-engine-audit-2026-11-01.md`) found an import engine already in place: `packages/import`, with adapters, a canonical model, a mapper, a report and a verifier. This work extends that engine. It does not add a second one.

It was built in two rounds: I1–I4 (the Qualtrics path, plus history and rollback), then I5–I8 (clarifications, Word, the review screen, behavioural equivalence and the corpora).

All test files are synthetic. No real client export was available. The AI step (I6) ran only against the fake provider.

## I1 — mapping decisions, timers, guidance, limits

### Mapping classes

`report.mapping` gives every source question one class, with a reason.

| Class | Meaning |
|---|---|
| `exact` | Native equivalent |
| `components` | Rebuilt from existing Studio parts; the note says what changed |
| `needs_runtime` | Rescript lacks the runtime for it; a placeholder keeps its place |
| `needs_js` | Carries custom JavaScript that changes its behaviour |
| `unsupported` | No equivalent; a placeholder keeps its place |

The class is derived from what the converter actually did, so it cannot drift from the conversion. A short table gives the sentence for types that need one:

- Captcha;
- drill-down (rebuild as `single.cascade`);
- highlight;
- gap analysis;
- heat map and hot spot;
- pick, group and rank;
- side by side;
- Timing and Meta;
- MaxDiff matrix.

### Qualtrics Timing

`MinSeconds` and `MaxSeconds` become S4b's native timer on the page that holds the question:

- `MinSeconds` → `minSeconds`;
- `MaxSeconds` → `limitSeconds` with `onTimeout: advance`;
- the clock is hidden.

A value of 0 means off, as in Qualtrics. If a page has a second timer, the first one is kept.

### Zip limits

Word and Excel files are zip archives. These limits apply:

- at most 5,000 entries;
- at most 100 MB per part and 300 MB in total;
- a compression ratio above 400:1 (and over 1 MB) is refused as a zip bomb;
- inflating stops at the cap even when the header lies about the size.

### Malformed QSF files

These five shapes return a reason, never an exception: truncated, empty, a non-list element array, null payloads, and a missing block.

### Corpus

Corpus file `04-large-121-questions.qsf` has:

- 121 questions in 12 blocks;
- page timers;
- chained display logic;
- panel redirects with piped `PID`;
- a script that holds Next for 3 s;
- a drill-down question.

## I2 — the dependency graph (`report.graph`)

`buildImportGraph(canonical)` works over the SOURCE, before mapping. It returns:

- **Nodes:** question, block, branch, embedded field, end, quota, script.
- **Edges,** from the element that depends to what it depends on: display, skip, skip target, branch, inside, piping, carry-forward, loop, quota, embedded assignment, script read/write, redirect.
- **Execution order.**
- **Embedded-data map:** where each field is set (sample list, flow or script; before the questions or during), every read, and whether it is defined at all.

It also lists these findings:

| Finding | What it covers |
|---|---|
| `missing_reference` | Question, choice, row, skip target block, carry-forward source, loop source, piped question |
| `circular_dependency` | Mutual dependencies; backward skips |
| `forward_reference` | A rule reads a question that is asked later |
| `unreachable` | Not in the flow, or only inside never-true branches. The adapter's parked unused blocks are named as such |
| `broken_branch` | Always false, or unreadable |
| `undefined_embedded` | Read but never set |
| `embedded_used_before_assignment` | Read before the flow sets it |
| `unused_embedded` | Set but never read (info) |
| `invalid_redirect` | Not a valid http(s) URL |

## I3 — JavaScript migration (`report.scripts`)

`analyzeQualtricsJs` is static analysis: it never runs the code. It reads:

- the hooks (`addOnload`, `addOnReady` → `on_load`; `addOnUnload`, `addOnPageSubmit` → `on_submit`);
- what the code reads and writes;
- 17 known Qualtrics and browser patterns, and what each becomes here.

It gives one verdict:

| Verdict | When | What the importer does |
|---|---|---|
| `compatible` | Every call has an equivalent | Adds a translated script, "Migrated JS … (review)". It passes the real S0 script check and is switched off |
| `native` | The code hides Next and shows it after N ms | Sets a page timer with an N-second minimum on that page (never over an existing minimum). Embedded writes are translated separately |
| `partial` | Some calls need a person | The findings say which and how (for example `setChoiceValue` → a punch rule) |
| `incompatible` | It needs DOM, jQuery, the network or redirects | Kept for reference only |

The original script always stays switched off. Its notes carry the verdict.

## I4 — import sessions (migration 0080)

Every `phase=run` records a session. The response's `session` field names it.

### What a session holds

- the file, in the private `rescript-imports` store, for **90 days**;
- the canonical model (up to 4 MB);
- a report digest: mapping classes, graph findings, fidelity totals, script verdicts and the summary;
- for a merge, the survey as it was before the import (up to 4 MB).

### Status

A session moves forward only:

- `analyzed` → `applied`, or `analyzed` → `discarded` (the preview was cancelled);
- `applied` → `rolled_back`;
- `failed` when the import did not produce a survey.

### Routes

| Route | What it does |
|---|---|
| `GET /api/import/sessions[?surveyId=]` | The history, newest first, for the caller's organisation |
| `GET /api/import/sessions/{id}` | One session: summary, digest, decisions |
| `POST /api/import/sessions/{id}` | `{action: "applied", surveyId?}` or `{action: "discarded"}` |
| `POST /api/import/sessions/{id}/rollback` | Roll back an applied import (below) |

`applied` needs `project.read` on the new project, or `survey.edit` plus the editing lock for a merge.

### Rollback

- **Merge:** the route returns the prior survey. The editor applies it as one edit, so ⌘Z brings the import back. It needs `survey.edit` and the lock.
- **New project:** the project is deleted through the project DELETE route (`project.delete`, its files, its audit record). This is **refused once the project has responses**: a rollback never deletes collected data.

New audit events record both: `survey.import_applied` and `survey.import_rolled_back`.

### Housekeeping

The weekly housekeeping removes source files whose 90 days are up, clears their key, and keeps the session as history.

### Without a database

With no database (the sandbox, or a local Studio), a process-wide memory store answers instead: the newest 100 sessions, lost on restart.

Sandbox sessions are visible only where the AI is the fake provider. An id that is not a sandbox session gets 401 without a sign-in, so nothing reveals whether it exists.

### In the Studio

- The import card says the run was recorded and until when the file is kept.
- **Roll back this import** appears on applied imports.
- The Intelligent welcome card lists **Recent imports** (the last 5) with their outcome.

## I5 — the clarification engine (`report.clarifications`)

When the source leaves a decision open, the engine asks one specific question instead of guessing. Kinds:

- `missing_condition` — "ASK ONLY IF THEY OWN A CAR": the alternatives are the closed questions just before it;
- `missing_target` — "SKIP THIS QUESTION IF NO" without a destination;
- `randomize_scope` — "RANDOMIZE" over a list that has special answers;
- `embedded_source` — "STORE THE REGION" without saying where it comes from;
- `conflict` — two rules on one question that no respondent can satisfy together;
- `undefined_reference` — a rule that names a question the source does not have (from the I2 graph).

Each has a recommended answer with its reason when the rules can make one, and structured alternatives. A decision is checked before it is applied (`applyDecisions`), works on a copy, and is remembered in the import session. `POST import/sessions/{id}/decisions` re-analyses with all decisions so far. "Leave it" closes the question and records "left to do in Studio".

## I6 — Word: AI-assisted interpretation, pictures, nested tables

- For a question with no rule-based recommendation, `POST import/sessions/{id}/suggest` asks the model to choose. The model sees the instruction and the engine's numbered, already-checked choices, fenced as untrusted data, and may return only an index or nothing. A suggestion is labelled as the AI's, is not pre-selected, and is applied only when a person picks it. One metered request (`import_suggest`). With the fake provider a deterministic word-overlap stand-in answers.
- Pictures in `word/media` are read with their alt text. Under 300 KB they are inlined in the question text as `data:` images; larger ones are listed as assets to upload.
- A table inside a table cell is flattened into that cell as `a | b` lines.

## I7 — the review screen

"Open full review" on the import card opens a dialog with five tabs: Summary (counts), Compatibility (every element in one of six categories — fully supported, supported with conversion, requires additional configuration, partially supported, unsupported, requires clarification — with the reason), Flow & logic (the source flow in order, conditions in words, what each question depends on), Questions (the I5 panel) and Blocks (import only some blocks; re-analysed, and what the kept blocks refer to outside the selection is reported). Clicking an element opens the inspector: the element as read from the source beside its reconstruction (`GET import/sessions/{id}/inspect?source=`). Nothing in the review writes a survey.

## I8 — behavioural equivalence, corpora, lifecycle

### Behavioural equivalence (`verification.behaviour`)

Structure says every question is there; behaviour says the survey branches the same way. `packages/import/src/equivalence.ts` turns each rule of the source (its canonical form, before mapping) into two scenarios, condition met and not met, with what the source says must then happen:

| Rule | Met | Not met |
|---|---|---|
| Display logic on Q | Q is shown | Q is not shown |
| Skip from Q to a later T | T is shown and the question after Q is not | the question after Q is shown |
| Skip or terminate to an end | the interview ends with that status | it does not end with it |
| Branch | its first question is shown (or its end reached) | it is not |

Each scenario runs on the engine against the imported survey: the scenario's answers are fixed and every other question is answered by the "deepest" walker. It is reported apart from the structural check, as `pass`, `fail`, `not_testable` (with the reason: a quota condition, a field the survey's own flow sets, a reference to a missing question, a condition the reader could not read) or `not_run` (over 120 scenarios, or past the 8-second budget during an analysis). Nothing that was not run is counted as passed. The import card shows one line ("behaviour: 6 of 6 logic scenarios behave as the source says"), and the Fidelity report lists every scenario.

Driven conditions: an answer chosen / not chosen (single and multi), "N or more chosen", embedded data equal / not equal / greater / less, and AND / OR / NOT of those.

Two walker changes came with it:

- A page is now settled like the runtime's live page: a question whose display logic reads another question on the same page appears or disappears as that one is answered. Before, the walker judged visibility before any answer on the page.
- The "deepest" look-ahead only tries answers of questions something else reads (`readByOthers`). The path chosen is the same; it is faster.

And one engine change: `flattenVariables` grouped every answer per question once instead of scanning all answers for each question. A 150-question walk went from about 1.5 s to 0.3 s. The engine's 2,634 tests pass unchanged.

### Corpora

- `packages/import/corpus/word/` — seven synthetic `.docx` files built by `scripts/word-corpus-build.mjs`: simple, complex instructions, tables with a nested table and a picture, contradictory, missing information, poorly formatted, and large (150 questions, 10 sections, 30 rules).
- `packages/import/corpus/qsf-invalid/` — six broken exports: not JSON, truncated, no elements, elements not a list, a question without choices and a block naming a missing question, a flow naming a missing block.

What the corpora found, now fixed:

- Conditions on codes without a Q (`S1 = 2`, `A3 = Yes`) were not read. Any short letter prefix and a number is now a question code.
- "TERMINATE IF …" and "SKIP TO Q4 IF …" (the condition written last) were dropped without a word.
- An instruction in wording the reader does not know was dropped without a word; it is now reported where it was written. So is an instruction after the last question.
- A table that is not a grid was dropped; it is now kept as a table in the question text, with a note.
- A QSF whose `SurveyElements` is not a list imported as an empty survey; it is now refused with the reason. A block naming a missing question, and a choice question with no choices, are now reported.

### Lifecycle

`scripts/import-lifecycle-test.mjs` takes every corpus file through: read → map → schema → the pre-field deliverable check → three simulated respondents on the engine → CSV and SPSS export with a column for every answered question. 12 files, 108 checks, 0 failures. Publishing is not exercised: it is a database write that needs the Studio and Supabase.

The deliverable check flags one corpus file: in `03-brand-tracker-complex.qsf` a branch whose condition could not be read ("If device is mobile") is imported as applying to everyone, and the check reports it as an error before fielding. That is intended; the import report already says to set the condition.
