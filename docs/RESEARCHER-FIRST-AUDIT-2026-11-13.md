# Researcher-first workflow audit — 2026-11-13

Guiding principle: **maximum functionality, minimum complexity.** A researcher should be able to say what they want
and read back what the survey will do; the engine should carry validation, defaults and dependency handling.

This document records what was audited, what was changed in this pass, and what was only assessed. Nothing below
removed a setting or changed how a stored survey is read or run: every change is to wording, grouping and the order in
which controls are shown, plus two read-only engine modules that describe a flow element in plain language.

## The pattern applied

1. **Say what it does first.** Each element opens on one sentence generated by the engine from its real
   configuration ("Repeats 2 questions (Q2, Q3) once for each answer the respondent chose at Q1 — at most 3 of them,
   in random order.").
2. **Say what is wrong in plain words, with what to do.** *Fix* (will not work), *Check* (probably not intended),
   *Tip*. No codes, no schema paths.
3. **Only the decisions every user must make are up front.** The rest sits under one "More options" disclosure that
   is closed until a setting inside it is in use, and opens by itself when one is.
4. **Researcher words on the labels, stored values untouched.** "iteration" → "round", "references" → "item details",
   "aggregates" → "totals across the rounds", "break when" → "stop repeating once…".
5. **Smart defaults.** The engine picks the obvious starting point and the researcher corrects it.

## 1. Loop — redesigned (reference module)

| Before | After |
|---|---|
| Opened on source, filter, dimension, count, order, three rules, source-resolution, the reference table, aggregates, loop variable and the statement all at once | Sentence + checks, then **Repeat for**, **How many**, **Order**; everything else under **More options** |
| "Iterate over", "eligible if", "skip if", "break when", "references", "aggregates", "loop variable" | "Repeat for", "Only repeat for items where…", "Leave an item out when…", "Stop repeating once…", "Item details", "Totals across the rounds", "Name and data" |
| A new loop was an empty typed list the researcher had to wire | A loop placed after a multi-select starts as "each answer the respondent chose" at that question; otherwise unchanged |
| Problems appeared only in the diagnostics list | The card itself says e.g. "Q1 is asked after this loop, so the respondent has not answered it yet… Move the loop below Q1" |
| Selects stacked full-width | The first decisions read as a sentence on one line |

Engine: `packages/engine/src/loopGuide.ts` (`loopPlainSummary`, `loopChecks`, `loopExtras`, `suggestLoopSourceInFlow`).
The loop node is stored exactly as before; every `data-testid` is unchanged.

## 2. Other flow elements — sentence and checks added

Randomizer, quota check, end of survey, redirect, embedded data and branch now open on the same sentence + checks
(`packages/engine/src/flowGuide.ts`). A closed element with something missing shows **Needs attention** on its card.
Option labels were reworded, values unchanged:

- Randomizer order: "random (seeded shuffle)" → "random — a different order for each respondent"; Latin square and
  Williams keep their names in brackets after a plain description.
- Quota check, when full: "terminate / redirect / flag & continue / continue" → "end the survey (quota full) / send
  them to a link / let them continue, marked over quota / let them continue".
- End of survey: "complete / screened / quota full / terminated" → "Completed / Screened out (not eligible) / Quota
  full / Terminated"; "Redirect on finish" → "Then send the respondent to this link".
- Quotas tab: "hard / soft" now say what they do; the when-full choices match the quota check.
- Conditions and piping: "iteration" → "round"; "Expression (calc DSL)" → "Typed calculation".

## 3. Assessed, not changed in this pass

Priority is by how much a non-programmer is likely to be stopped. Control counts are the form controls in the
component's source, as a rough measure of what is on screen.

| Module | Where | Finding | Priority | Proposed change |
|---|---|---|---|---|
| Display / skip logic | `ConditionBuilder.tsx` (20 controls), `LogicDialog.tsx` | Builder is sound and already summarises a condition in words. The "Expression" mode sits beside the builder as an equal choice; operators lists are long | Medium | Keep the builder as the default; move "Expression" under an "Advanced" link; show the plain-language reading above the builder, not only on the card |
| Masking / list logic / carry-forward | `MaskingBuilder.tsx` (20 controls), `CarriedOptionsPanel.tsx`, `OptionLogicEditor.tsx` | Four related tools were given numbered plain titles in patch 0149, but "Auto punch", "punching" and "set expression" remain, and a researcher still has to know which of the four to open | High | One entry question — "Which answers should this question show?" — that routes to the right tool; rename "auto punch" to "select automatically" |
| List Fill | `ListFillPanel.tsx` (21 controls, no disclosure) | The densest editor left: source, selection, least-filled basis, tie-break, tracking and quotas are all visible at once | High | Same treatment as the loop: sentence, "what to pick from / how many", More options for balance and tracking |
| Quotas | `QuotasPanel.tsx` | Compact, but cell conditions are shown as generated text with no way to see which cells are unreachable | Medium | Sentence per quota ("Stops at 200 men aged 18–34"), checks for cells that can never fill. The "warn" when-full choice was left as is: its runtime meaning needs confirming before it is reworded |
| Embedded data | `EmbeddedDataEditor` | Name, type, source, value, default and condition per field. "Embedded data" itself is platform jargon | Medium | Call it "Saved values" in the UI with "embedded data" kept as a searchable alias; hide type (Auto) and default under More |
| Randomizer balance | `BalanceSettings`, `RandomizerDesignSettings` | Basis, claim order, per-quota-cell balance, abandonment timeout and weights are visible as soon as "even presentation" is ticked | Medium | Fold under More options; the defaults are already correct |
| Branching | `BranchEditor`, `BranchPaths` | "IF / ELSE IF" labels; otherwise clear. New checks now flag a path with no condition | Low | "If… / Otherwise if… / Everyone else" |
| Question validation, timers, scripts | `PropertiesPanel.tsx` (62 controls, 47 disclosures) | Already uses progressive disclosure heavily; the risk is the number of sections, not jargon | Medium | A "most used" group per question type at the top; needs usage evidence before reordering |
| Piping | `PipingPicker.tsx`, `InsertPipedText.tsx` | Picker is clear; token syntax is shown raw in the text | Low | Already renders chips in the rich editor; no change proposed |
| Custom scripts | `LegacyScripts.tsx`, code panels | Intended for programmers | None | Leave as is, keep out of the default path |

## 4. What was and was not verified

Verified by automated tests in this pass:

- Engine: `loopGuide.test.ts` (5) and `flowGuide.test.ts` (4) — sentences, checks, the suggested source, and that
  nothing reads mutate the node.
- Browser, Studio only: `scripts/loop-simple-test.mjs` (9) — summary, More options closed by default and open when
  in use, every setting still reachable, stored loop identical after opening, checks for a late source and an empty
  list, the suggested source on a new loop, and the sentence/checks on the randomizer, quota check, redirect and end.
- The Studio halves of `scripts/loop-test.mjs` (15 checks) and `scripts/master-demo-test.mjs` (9 checks) pass against
  the new editor.

Not verified:

- The respondent-side halves of `loop-test` and `master-demo-test` were not run in this pass (the two dev servers do
  not fit in the test sandbox's memory together). No runtime code changed.
- The reworded labels in the Quotas tab, List Fill, the condition builder and the piping picker have no browser test
  of their own; they are text-only changes covered by the type check and the unit suites.
- No researcher has used the new loop card. The claim that it is easier is a design judgement, not a measured result.
