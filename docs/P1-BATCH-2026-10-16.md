## The age test case, after the batch
Engine (`repro/qt/age-validation.mjs`): all four shapes — plain `numeric` with "age" wording, `semantic:"age"`, `integer`, and explicit integer rule — give the brief's expected verdict for 1, 100, 0, −1, 25.5, 101, blank, "abc", " 42 ", "1e2". Browser (`repro/browser/age-e2e.mjs`, fake provider → Studio → runtime preview): the question is stored with `integer`, `decimalPlaces 0`, `numberSign positive`, `semantic age`, the input is `inputmode=numeric`, and `25.5` / `abc` / `1e2` do not advance (the whole-number field refuses the `.`, letters and `e` at the keystroke; a pasted value is refused by the engine with "Please enter a whole number." / "Please enter a number."; the server replay refuses it again).

## Behaviour notes
- Rule order after a merge: what the action said first, what the type implies after (so a conditional rule stays first for the UI).
- `set_validation` still replaces the authored rules; it no longer removes the intrinsic ones.
- `semantic:"none"` is remembered so the wording-based inference never re-tags a question the author opted out.
- Option/row recoding runs on commit (blur/Enter), not per keystroke; a code that would clash or that nothing holds is refused with an error toast.
- SPSS: strings over 255 bytes are still cut (very-long-string record 7/14 remains unimplemented).
