# Research Engine — Phase 8: The project brief, the language corpus, waves across runs (10-10-2026)

**Source:** the three items proposed after the audit roadmap (Phases 1–7) closed, taken together as one phase: a *project brief* entity (the audit's §D "low" row "a project brief entity"), a *language regression corpus* built from what researchers actually type (so the recognisers and the lexicon are checked against real usage, and the sentences the engine hands on become the lexicon's backlog), and *wave trends across runs* (the one piece of §D's "findings synthesis beyond the plan" Phase 4 left open: Phase 4 reads waves inside one run; a tracker is run again). Every change has a regression test and the tests were mutation-checked. Nothing existing was removed: `set_research` keeps every field it kept, a run without a previous one has no comparison and no slide, a history without the new intent keys still makes a corpus (the record's source decides), the deck's and the report's existing sections are where they were.

## What was built

**The brief (`packages/schema`, `packages/engine`)** — `ResearchBrief { client?, businessQuestion?, decision?, background?, stakeholders[], deadline?, deliverables[] }` on `research.brief`. `set_research.brief` is a partial: the apply merges `{ stakeholders: [], deliverables: [], ...prev, ...given }`, so "the client is Acme" never loses the business question. `BRIEF_WORDS` names the fields in descriptions. `objectiveFromBusinessQuestion` turns a yes/no question into an objective ("Is Brand A losing younger buyers?" → "Understand whether …", a wh-question → "Understand why …", a statement kept). The brief recogniser sits between `objective` and `audience`.

**The corpus (`packages/engine/src/languageCorpus.ts`)** — `LanguageCorpus { version: 1, exported, survey, definition, entries }`; `CorpusEntry { text, kind, category?, ops?, selected?, count?, at? }`; kinds are the engine's plus `model` and `grammar`. `readingOf` is the compact reading the corpus records (kind, category, ops, understood). Verdicts: same (kind equal; for actions, ops equal), better (model's or grammar's → the engine's), worse (the engine's → the model's), changed (anything else — a sentence refused as "already so" against the survey as it is now is *changed*, honestly). The backlog is what is *now* the model's, most said first.

**Waves (`packages/analytics/src/waves.ts`)** — `KpiSnapshot`, `KpiDelta`, `FindingChange`, `VerdictChange`, `WaveComparison`; `kpiSnapshot`, `compareRuns`, `findingKey`, `waveNumbers`, `describeSince`. `AnalysisRun.kpis` and `.since`; `runPlan` fills the KPIs; `briefText` prints both; `narrative.runNumbers` admits the wave numbers; `deck.ts` `waveSlide` and the `wave_change` slide type (drawn by `export/deck.ts` as a table with a legend and the changes beside); `export/docx.ts` the section. `apps/studio/lib/analyticsRunStore.ts` `pickPrevious(rows, datasetKind)`; `apps/studio/lib/analytics.ts` `previousRun(db, surveyId, spec, before)`; `runPlanFor` attaches the comparison before storing; the cron's milestone runs get it for free.

**The Studio** — `ResearchDesignEditor` `BriefSection`; `CopilotPanel` `LanguageSection` (History); `FindingsTab` `fd-kpis` / `fd-kpi` (`data-verdict`, `data-significant`) / `fd-kpi-delta` / `fd-since` / `fd-since-finding` / `fd-since-verdict` / `fd-since-gone`; `useCopilot.exportCorpus`; routes `POST /api/copilot/corpus`, `GET /api/briefs`; `IntelligentView` records the engine's reading on the grammar path too. The model's `set_research` example in the system prompt gains the brief's fields.
