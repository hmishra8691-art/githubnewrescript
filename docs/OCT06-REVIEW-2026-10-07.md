## Root causes and fixes

**W1: Layout**

- **Cause:** `optionsClass` turned an unset value into "auto", and every renderer had its own fallback.
- **Fix:**
  - Added `layoutColumns(q)` in the engine (`rendererReads.ts`). Unset now means 1 column, capped at 5.
  - The Studio's Layout control, the radio / checkbox / button lists, `colsClass` and `gridColumnsStyle` all read this one function.
  - Grid variants keep the counts they were designed with (Card 2, Image 3, Flip 3, Icons 4 and so on). The builder shows that number instead of "auto".
  - "Horizontal row" is still available where it was before.
  - Added `cols-5` CSS for every grid, with responsive fallbacks.

**W2: HTML and CSS in question text**

- **Cause:** `sanitizeHtml` treated every `<style>` block as Word paste residue and deleted it on save. That is why the chess board fell into a single column. Separately, the Text / HTML Block's HTML Content was injected raw, so its `body {…}` rules restyled the whole preview page.
- **Fix:**
  - `sanitizeHtml({ keepStyles })` keeps the author's stylesheet and still removes Word's. `sanitizeStylesheet` strips executable CSS.
  - `scopedHtml.ts` unwraps pasted page wrappers (doctype, html, head, body, title).
  - It scopes every rule under the question with `[data-rs-scope]`, so `body`, `html`, `:root` and `*` refer to the question itself.
  - `@media` blocks are respected and also applied in the device preview (`.rs-viewport.mobile/.tablet`).
  - `renderRichContent` is the one pipeline used for question text, instruction and the HTML block.
  - In the Studio's visual editor, styles are shown scoped to the editor surface (`rteStyles.ts`). The author's original CSS is restored when saving.
  - A question text that carries its own stylesheet is rendered as body text rather than as a heading, matching the block.

**W3: Insert Media layout**

- Added `mediaGroupHtml` and `mediaGroupFromAttrs`. The layout is stored in data attributes on the group element inside the question text, so the Studio, preview and live survey all read the same markup.
- Renderer CSS handles all four layouts.
- `enhanceMediaCarousels` adds the ← → buttons and dots. Swipe works through native scroll-snap.
- The dialog has a Media layout section with columns, gap and alignment. Editing an item inside an existing group also edits that group's layout.
- New fit options: `original` and `custom`. Both survive the round trip through a `--rs-fit` custom property.

**W4: Date/Time Range**

- `FormattedDateField` is shared by the Date Picker and both ends of the range.
- Added the `DD MMMM YYYY` and `MMMM DD, YYYY` formats. Month names are now parsed strictly ("Septober" is refused).
- A variant-keyed Studio block (`variant:datetime.date_range`) provides Range type, Date format and Time format (12h, 12h + seconds, 24h, 24h + seconds).
- The new `fields.range` policy hides the per-end type select and the placeholder.
- The variant id is unchanged, so stored answers are not affected.

**W5 / W6: Numeric**

- `customAffix` covers `affixText` / `affixSide`. Quantity's older `unitLabel` is read the same way, so there is one field rather than two.
- `affixFor` now gives the selected currency precedence over a legacy typed symbol.
- The "Or type a symbol" input is gone. A legacy typed value is shown with a button to move or remove it.
- Numeric List fields take `row.meta.affixText` / `affixSide`, and the box width comes from `numericBoxCh`, based on the field's bounds and decimals.

**W6b: false "leftover field" warnings**

- **Cause:** `migrateQuestionType` / `staleFields` treated any setting the shape table did not list as dead. That included `currencyCode`, `symbolSide`, `optionSearch`, `validationPosition` and every October setting. The warning appeared, the Studio offered to delete these working settings, and every type change silently stripped them.
- **Fix:** only settings the table claims can be leftover. Added a `number_input` group.

**R1: Embedded Data URL**

- `EmbeddedDataType` now includes `"url"`, so the data model holds `{ name, dataType: "url", value }`.
- `checkUrlValue` validates the value:
  - Accepts `http` and `https` only (the editor says so), with ports, paths, query strings, nested or encoded parameters and fragments.
  - Rejects other schemes, spaces and URLs without a domain. The value is never rewritten.
- `coerceEmbedded("url")` stores the value exactly as written. An invalid value becomes no value, with a reason, the same as the other types.
- `resolveUrlTemplate` uses a URL field that starts a redirect template as the address itself. Before, it was percent-encoded into a relative path. In a parameter position it is still encoded, so its own `?&=` survive.
- `validateRedirectUrl(url, def)` accepts a URL field as the whole address.
- The structural lint blocks release when a fixed value or default value does not match its declared type.
- The Studio editor offers URL as a type, with URL-friendly inputs, an http(s) hint and a preview of exactly what will be stored.
- The import canonical type and the AI action type lists include `url`.
- Untyped fields behave exactly as before.

**R2: one canonical content (`question.text`, plus the instruction)**

- `normalizeQuestionContent` runs as a `z.preprocess` on `Question`, so every parse migrates legacy data. That covers Studio load, JSON apply, preview, runtime deployment, import, clone, version restore and the API routes.
  - **Text / HTML block:** `customHtml` becomes the text. A builder-only label is kept in Programmer notes.
  - **Any other type:** "Custom HTML above the input" is appended to the instruction.
  - **Custom Component:** keeps `customHtml` as its template, which is a different responsibility.
- Removed the HTML Content textarea from the question editor. In the Custom code panel, Custom HTML is replaced by a note, except on a Custom Component, where it is labelled "Component HTML".
- The renderer no longer reads `customHtml` for any type except a Custom Component.
- The Text / HTML block renders its text through the shared pipeline. Frames, objects and forms are still allowed there, as they always were; scripts and event handlers are removed.
- The canvas view and the templates no longer write `customHtml`.
- The AI action `set_custom_html` appends to the instruction for ordinary questions.
- The survey diff now includes instruction changes.

## Audit of question types (R2)

`customHtml` was the only rival content field:

- Text / HTML Block: content (migrated into the text).
- Every other type: "above the input" (migrated into the instruction).
- Custom Component: template (kept).

`text` and `instruction` are the content. `description` is not drawn or edited anywhere. No other duplicate fields were found in schema, builder, properties, runtime, preview, import, export, localisation or templates.

## Conflicts and interpretations

- **W1 vs. grid variants:** "1 column default for all questions". Option lists now default to 1. Variants built as grids (Card, Image, Flip, Icons, Comparison) keep their designed count, which the builder shows as a number. I did not force those to 1, because that would change how existing surveys look. Say if you want them set to 1 as well.
- **W2 vs. security:** CSS is kept and scoped, not passed through raw. `@import`, `url(javascript:)`, `behavior` and `expression()` are still removed.
- **The question's own Custom CSS** (Custom code panel) is still unscoped, as it was before. Authors use it deliberately to target the page.

## Data and schema changes

All are additive and optional:

- `EmbeddedDataType` adds `url`.
- Settings `affixText` and `affixSide`.
- `dateFormat` adds two formats.
- `MediaDisplay.fit` adds `original` and `custom`.
- Variant policy `fields.range`.
- `builder` gains `rowsAddLabel` (from the previous round).
- The Date Range variant's label is now "Date/Time Range"; its id is unchanged.
- The content migration (`normalizeQuestionContent`) runs on parse, is idempotent, and is the only reader of legacy `customHtml`.
