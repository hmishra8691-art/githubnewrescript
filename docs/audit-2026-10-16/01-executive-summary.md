# 01 · Executive summary — Rescript Studio platform audit (2026-10-16)

**Scope.** Full-platform audit at commit `b0dbe08` (`main`): architecture, every question type, validation, the logic engine and matrix editor, Conjoint/MaxDiff/List Fill, Intelligent Mode end to end, data cleaning, analytics, document exports, runtime scripting, schema and migrations. Eight parallel code-level audits plus orchestrator-run browser reproductions (Studio + runtime dev servers, fake AI provider) and read-only queries against the active Supabase project. No source files were changed. Tests executed: typecheck clean; 3,929 unit tests across packages and Studio, all green; the 148-suite browser corpus run on 2026-10-15 against this same commit (142 pass, 6 known pre-existing failures); 20+ purpose-built reproduction scripts.

**Overall readiness: not production-ready for research-grade use; the foundations are strong.** The engine is well-tested (1,855 tests), the UX script pipeline, analytics computation, cleaning engine and export catalogue are real and mostly correct. What blocks a release is a short list of integrity and validation defects, most of them small to fix, plus three capability gaps the brief treats as mandatory (semantic validation, geographic hierarchy, two of the four research documents).

## The findings that matter most
1. **P0 — the respondent save API trusts the client** (`RUNTIME-01`). `/api/session/save` writes any `answers`, `status` and `step_index` it receives; nothing on the server re-validates against the deployed definition. Combined with `RUNTIME-02` (sessions can be started on password-protected or closed surveys through the API), any respondent-side actor can fabricate complete responses that flow into quotas, analytics and exports.
2. **The age-decimal defect is reproduced and has one root cause** (`QT-01`/`AI-01`). `shapeQuestion` *replaces* a question's validation list with whatever the model sent, so an `integer` (or `email`, `phone`, `url`, `zip`) question loses its intrinsic rule the moment the AI adds min/max. Verified end to end: Intelligent Mode → Apply → runtime preview accepts `25.5` for both `numeric` and `integer` age questions. A second, independent gap (`QT-02`): nothing infers "whole number" from "age"; no semantic validation registry exists. `"abc"` and `"1e2"` also pass numeric bounds (`QT-03`).
3. **Hand edits in the Studio bypass the engine's reference integrity** (`LOGIC-01`, `LOGIC-02`). Changing an option or row code in the Options editor leaves display logic, quota cells, masks and calcs pointing at the old code (only a warning lint fires); the Intelligent-Mode path does the recode correctly. Calculations also resolve question codes to `null` whenever code ≠ variable name (`LOGIC-03`) — silently.
4. **MaxDiff is unsafe in three places** (`METHOD-01/02/03`): a required task accepts best==worst and half-answered tasks (browser-verified); analysis reads version-1 design rows for every respondent (27% of choices dropped on a 4-version design); one best==worst answer makes the whole analysis "not computable".
5. **Two export/access defects**: SPSS `.sav` replaces every non-ASCII character with a space (`DOC-06`, data loss for any multilingual study); the response download is gated on `responses.read`, so a `viewer` can export full datasets (`DOC-07`).
6. **Matrix logic editor**: the October-15 fix holds (column and value pickers never co-exist on a categorical grid — browser-verified). The remaining "duplicate information" is cosmetic/usability: the rating-matrix value list reads `1: 1 · 2: 2 …`, composite columns get all ~40 operators regardless of type, and ~45 `SYSTEM_*` variables are listed inline with questions (`OR-04/05/06`).
7. **Base of 20**: not reproducible from stored data (no run or cached result carries n=20; the largest survey's possible scopes yield 0, 2, 17, 24 or 31). No hard-coded 20 exists. The mechanism is scope silently reducing the base (LIVE-only, completes-only, "clean" quality, answered-only, version-pinned) without the caption saying so; one caption component fixes the class (`OR-03`). One real base defect was found: several tables show the all-cases base in the table while the header shows the answered base (`ANALYTICS-02`).
8. **Intelligent Mode is structurally sound** — 70 ops, all coerced, applied on a clone and re-parsed; plan-first generation checkpoints per item with bounded retries. Gaps: unexplained-error wording for 401/400 (`AI-04`), memory not persisted (`AI-05`), custom CSS applied without the gate (`AI-06`), no action to create designs or validation scripts (`METHOD-08`, `LOGIC-13`).
9. **Research documents**: Questionnaire/Programming Spec exists and is good; Research Plan exists as a proposal with gaps; Analysis Framework/SAP and Data-Cleaning Plan are missing (`DOC-02/03/04`). All four can be generated from the existing definition + plan + quality config — no new source of truth needed.
10. **Cleaning**: a real 70-rule engine with override and audit trail; but quality is **off by default** on every survey (`CLEAN-03`), soft-deleted rows still act as peers (`CLEAN-06`), and duplicate detection drops both members of a pair (`CLEAN-09`).

## What is confirmed working (do not re-audit)
Engine logic (nested AND/OR/NOT, 16 operators, matrix refs `Q1.R1.C1`, masking, piping, quotas, loops, calcs, auto-punch — 1,855 tests); analytics bases and statistics (controlled dataset 83/84 checks; single `compute()` for dashboard, charts, crosstabs, exports, stories); CBC/MaxDiff design generators (balanced, prohibitions honoured, seeded per-respondent versions); aggregate logit recovers planted utilities; cleaning engine deterministic with full audit trail; exports (Excel, SPSS, SAS, Stata, CSV, JSON, questionnaire .docx); version immutability, revision CAS, double-submit protection; RLS on all 92 tables, service-role only; the unified UX script pipeline.

## Recommendation
Fix in three small, independently shippable batches before any feature work (see `12-implementation-roadmap.md`): **Batch 1 (≈1 week)** — the P0 and the eight P1s that are ≤1 day each (RUNTIME-01 behind a flag, QT-01/AI-01, LOGIC-01, LOGIC-03, METHOD-01/02/03, DOC-07, RUNTIME-02). **Batch 2 (≈2 weeks)** — semantic validation registry (QT-02, QT-03), SPSS UTF-8 (DOC-06), List Fill empty-run, quality-on-by-default, analytics base caption, the matrix-editor cosmetics. **Batch 3 (≈4–6 weeks)** — geographic hierarchy, SAP + cleaning-plan documents, `create_design`/`create_script` ops, methodology capability registry, sandboxing `def.scripts` and `custom_component`, server-side quota capping. Nothing in batches 1–2 needs a database migration; batch 3 needs one additive column at most.
