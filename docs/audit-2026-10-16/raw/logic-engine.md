## Expression grammar (packages/engine/src/logicExpression.ts)

`parseLogicExpression(def, text)` → `Condition`; `formatCondition(def, cond)` prints it back. Reference = `HEAD[.SEG2[.SEG3]]`:
- HEAD: question code / variable name / id, `loop.*`, `CURRENT_ITEM.*`, `<loopVar>.<col>`, `quota.*`, `@option.*`, named expression (`:663-686`).
- SEG2 (`resolveRowOrOption` `:1252-1280`): row code, option code, `R<n>` (code or position), `O<n>`/`A<n>`, or a **label** (`Q1.Service`). Categorical grid + 2 segments: `Q1.C3` = column-only ("any row rated 3") (`:713-721`).
- SEG3 (`resolveColumnOrOption` `:1283-1303`): composite column id / variableStem, option code, `C<n>`/`O<n>`/`A<n>`. **No label resolution on SEG3** (`Q1.R1.Great` fails, `Q1.Service.Great` fails).
- Canonical categorical-grid cell: `{rowCode, columnId, operator: selected|notSelected}` with **no value** (`gridCell.ts:1-40`, `normalizeGridRule`). Comparisons: `{rowCode, operator, value}` with no columnId.
- Evaluation: `evaluate.ts resolveSourceValue :229-346` — row drill (`:269-283`), column-only across rows (`:284-324`), cell sets evaluated existentially for value operators (`EXISTENTIAL :500-511`, `:782-791`), categorical `selected` with columnId and no value (`:773-780`). AND/OR/NOT(NOR) with vacuous-group skipping and depth cap 200 (`:886-950`).
