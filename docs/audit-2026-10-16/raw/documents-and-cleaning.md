## Part B — CLEAN: data cleaning / response quality

### B.1 What is implemented

`packages/quality` is a pure engine (`assess(input) → QualityAssessment`, no I/O) with a server glue (`server.ts`) used by both the runtime (on the final save of a session) and the Studio (per-response re-assess, survey-wide recompute). 70 built-in rules in 15 categories (counted from `RULES`): timing 12, matrix 8, consistency 4, pattern 8, attention 3, open_end 11, interaction 3, navigation 4, device 3, network 3, bot 3, duplicate 2, cluster 2, screener 3, custom/history 1. Enabled by strictness preset: relaxed 30, standard 59, strict 68, very_strict 70. 21 rules are informational by default (shown, cost quality, never move the verdict). 31 rules need runtime telemetry, 16 need peers, 29 need neither (timestamps and answers only).

Mapping to the brief's list:

| Brief item | Status | Rules / evidence |
|---|---|---|
| Speeding | IMPLEMENTED | `timing.overall_speeding` (timestamps only; vs median of ≥ `minPeers`=30 completes, else reading-time estimate with `estimateConfidence` 0.6 and a caveat), `page_speeding`, `question_speeding` (first-answer latency), `matrix_speeding` (s/row), `openend_speeding` (chars/s minus pasted), `reading_time` (wpm), `short_dwell`, `uniform`, `idle_then_rush`, `entropy`, `acceleration` (info), `pattern_match`, `screener.fast`, `bot.machine_timing` — `rules/timing.ts` |
| Straight-lining | IMPLEMENTED | `matrix.straightline` (minRows, sameShare, gridShare), `reverse_straightline` (polarity-aware), `diagonal`, `alternating` (folds reverse-worded rows first), `low_variance`/`midpoint`/`extremes` (info), `signature_match` (expected-twins test against peers) — `rules/matrix.ts` |
| Duplicates | IMPLEMENTED | `duplicate.answers` (rarity-weighted agreement; informational unless literally identical), `duplicate.multi_signal` (agreement + device/IP/nav/timing/open-end), `device.duplicate`, `network.duplicate_ip` (info), `network.ip_density`, `openend.duplicate` (shingles), `matrix.signature_match`, `cluster.coordinated`/`burst` (union-find clusters, final ids on recompute), `screener.repeat_attempts` — `similarity.ts`, `rules/behaviour.ts` |
| Missing data / item non-response | **MISSING** | No rule for blank required items, item-nonresponse rate, break-off position. Only `openend.probe_ignored` (follow-ups left blank, info) and `pattern.nonsubstantive` (DK/other share, info). `grep -i "missing\|blank" packages/quality/src` confirms |
| Contradictions | IMPLEMENTED (partial) | `consistency.impossible_path` (answer present where display logic is now false), `attention_pair` (undeclared repeated question), `frequency_quantity` (never + positive quantity, same block), `piping`, `openend.contradiction` (text names an unselected option) — `rules/attention.ts`, `rules/openEnd.ts`. No generic cross-question constraint language beyond custom rules |
| Attention checks | IMPLEMENTED | `attentionCheck` on a question (`explicit`, `instruction`, `trap`, `reverse`, `repeat`, `knowledge`; `schema/quality.ts:189-198`), `attention.failed`, `multiple_failed` (count), `knowledge_gap`; `AttentionCheckEditor.tsx` |

| Geo validity | PARTIAL | `device.locale_timezone` (informational, `expectedTimezonePrefix` defaults to "" = never fires unless configured) and `network.risk_provider` (needs `SYSTEM_NETWORK_RISK` from an external provider hook — none configured in repo). No IP-country vs stated-country, no postcode/region validity (analytics has a geo module for charts only) |
| Open-end quality | IMPLEMENTED | 11 rules: too_short, gibberish, repeated, generic, irrelevant, contradiction, duplicate, ai_like (info), pasted (info), probe_ignored, probe_echo — `rules/openEnd.ts` |
| Audio / video integrity | **MISSING in quality** | Interviews record neutral telemetry events (`recording_too_short`, `upload_failed`, `transcript_unavailable`, `visibility_hidden` …) with an explicit design rule that no score or verdict is derived (`packages/interviews/src/telemetry.ts:1-20`). Survey media answers get no integrity rule |

Thresholds and configurability — IMPLEMENTED: every rule's thresholds are a `params` table with a default per strictness (`catalogue.ts`); per survey a researcher overrides `enabled`, `severity`, `role`, `weight`, `qualityWeight`, `params`, `questionIds` per rule (`RuleSetting`), adds custom IF/THEN rules with points and a classification floor, sets classification bands (20/40/60/80), evidence policy (`correlated` vs `independent` combination, `minPeers`, `estimateConfidence`, `minPopulation`, `flagged` rule, `flaggedMinCategories`), telemetry switches, retention days, `maxPeers`; six built-in profiles and customer-level saved profiles (`quality_profiles` table, `profiles.ts`, `quality/profiles/route.ts`). `configFingerprint()` is stamped on every assessment and the dashboard marks rows scored under other settings. The Studio editor (`QualitySettings.tsx`, 639 loc) renders the catalogue.

### B.3 Summary of the clean-dataset contract (as implemented)

1. A response is assessed once at its final save if `def.quality.enabled` (runtime), and again on demand (Studio). Assessment = flags + scores + classification (CLEAN / REVIEW / SUSPICIOUS / HIGHLY_SUSPICIOUS / CRITICAL by bands) + verdict (PASS / REVIEW / FLAGGED by evidence policy) + reasons + `configHash`.
2. The researcher's decision (KEEP / REMOVE / REVIEW_LATER) overrides the classification; it is data on the row and a row in `response_reviews`.
3. `dataset=clean` = KEEP ∪ (unreviewed ∧ CLEAN-or-unscored) − REMOVE. `dataset=all` = everything not soft-deleted (including REMOVE). Soft-deleted rows are in no dataset (except, wrongly, as quality peers — CLEAN-06).
4. The same predicate drives the Data tab, every export format and the analytics dataset; the statistical formats just do not label the rows (DOC-08).
