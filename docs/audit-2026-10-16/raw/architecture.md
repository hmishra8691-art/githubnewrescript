## 3. Control plane vs data plane (schema, RLS, writers)

Source: `supabase/migrations/0001..0054` (54 files, 11,745 lines) parsed with a session helper (not kept); the resulting table and function lists are `repro/arch/tables.txt` and `repro/arch/sql.txt` (full dump: `docs/audit-2026-10-16/repro/arch/sql.txt`), and table/RPC call sites with `a session helper (not kept)` (`docs/audit-2026-10-16/repro/arch/tables.txt`). 92 tables, 0 views, 119 distinct functions (many redefined across migrations). **All 92 tables have RLS enabled**; 151 `revoke all on function` statements. Every app query runs as `service_role` (`supabaseAdmin()` in each app's `lib/admin.ts`, `supabaseService()` in `apps/studio/lib/authServer.ts`), so RLS is a safety net, not the access-control path — the per-route guard (`apps/studio/lib/guard.ts`, capability model in `@rescript/access`) is.

Policy helpers: `current_customer_id()`, `current_role()` (0001), `rescript_project_role(user, survey)`, `rescript_is_platform_admin(user)` (0008). Write policies for `authenticated` exist only on `surveys` (0001 `surveys_write` ALL for programmer/platform_admin; 0008 `surveys_editor_write` UPDATE), `themes`, `design_files`, `project_comments`, `notifications`, `access_settings`, `profiles` — everything else is select-only for members or `using(false)` (service-role only).

## 4. End-to-end data flow (concrete hops)

1. **Definition JSON in the editor** — `apps/studio/components/studio/store.tsx` holds the `SurveyDefinition`; autosave `PUT /api/surveys/[id]/draft` (`store.tsx:415`) → `apps/studio/app/api/surveys/[id]/draft/route.ts:41` (`requireEditRight`, `SurveyDefinition.safeParse` at :53, then `db.rpc("rescript_save_draft", …)` at :104 with the revision guard from migration 0004) → `surveys.draft_definition`, `surveys.revision++`. Client-side helpers: `lib/draftSave.ts` (`serialRunner`, `canonicalJson`, `isOwnWrite`), `lib/draftSnapshot.ts`.
